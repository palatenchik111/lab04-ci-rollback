# Lab04 — стартовый проект для GitHub Actions и отката

Учебный ASP.NET Core API на .NET 9 и один тест xUnit. Проект соответствует приложению А лабораторной работы № 4. Начальное состояние: версия 1.0, имитация сбоя выключена, тест ожидает результат 4.

## Что требуется

- .NET 9 SDK (проверьте `dotnet --list-sdks`). Установленный только .NET Runtime не подходит.
- Git и аккаунт GitHub для основной работы.
- Docker Desktop с Linux containers для этапа развертывания.
- PowerShell и curl.exe.
- Интернет для восстановления NuGet-пакетов.

`global.json` выбирает установленный SDK 9.0, начиная с 9.0.100, с разрешённым переходом на более новую feature-версию 9.0. Если установлен только SDK 8 или 10, установите также SDK 9. В файлах лабораторной используется именно .NET 9.

## Как перенести проект в свой репозиторий

1. На GitHub создайте репозиторий `lab04-ci-rollback` с README.
2. Скопируйте HTTPS-адрес через Code → Local → HTTPS.
3. Откройте PowerShell в папке для учебных проектов:

```powershell
git clone "АДРЕС_ВАШЕГО_РЕПОЗИТОРИЯ" lab04-ci-rollback
Set-Location lab04-ci-rollback
```

4. Распакуйте ZIP отдельно. Скопируйте **содержимое** папки `Lab04_GitHub_Starter` в клонированную папку `lab04-ci-rollback`, включая `.gitignore`. README можно заменить версией из архива. Не создавайте дополнительный вложенный уровень: `Lab04.sln` должен лежать прямо в корне репозитория, рядом с `.git`.
5. Выполните команды проверки из следующего раздела.
6. Отправьте стартовое состояние:

```powershell
git status
git add .
git commit -m "Add starter API and test"
git push
```

Если Git запрашивает имя и email автора, настройте свои данные для репозитория. Не помещайте токены в файлы проекта.

## Проверить сборку и тест

Все команды выполняются из папки, где расположен `Lab04.sln`:

```powershell
dotnet --version
dotnet restore Lab04.sln
dotnet build Lab04.sln --no-restore -c Release
dotnet test Lab04.sln --no-build -c Release
```

Ожидается один успешно выполненный тест `Add_TwoAndTwo_ReturnsFour`. После ошибки не переходите к следующей команде.

Для Visual Studio откройте `Lab04.sln`. Требуется версия Visual Studio, поддерживающая установленный SDK .NET 9; запуск через CLI не требует Visual Studio.

## Проверить API без Docker

В первом окне PowerShell:

```powershell
dotnet run --project Lab04.Api/Lab04.Api.csproj --no-launch-profile --urls http://127.0.0.1:8080
```

Дождитесь сообщения о прослушивании порта. Во втором окне:

```powershell
curl.exe --fail-with-body --max-time 10 -i http://localhost:8080/health
$LASTEXITCODE
```

Ожидаются HTTP 200, JSON `{"status":"ok","version":"1.0"}` и код завершения 0. Интерфейса сайта и Swagger в стартовом проекте нет; используйте `/health`, а не корневой адрес.

Остановите API через Ctrl+C перед запуском Docker-контейнера, чтобы освободить порт 8080.

## Дальнейшая работа

Перейдите к разделу 5 выданной лабораторной. Приложение А повторно выполнять не нужно: решение, проекты и тест уже созданы.

В ходе лабораторной студент самостоятельно:

1. Включает `TreatWarningsAsErrors` в `Lab04.Api.csproj`.
2. Создаёт `.github/workflows/ci.yml` по инструкции.
3. Меняет ожидаемое значение теста с 4 на 5, получает ошибку CI, затем возвращает 4.
4. Создаёт `Dockerfile` и `.dockerignore` по инструкции.
5. Собирает образ 1.0 и проверяет `/health`.
6. В `appsettings.json` задаёт Version = "2.0" и SimulateFailure = true, собирает образ 2.0.
7. Получает HTTP 503 и выполняет откат на сохранённый образ 1.0.

Workflow, Dockerfile и включённый контроль предупреждений намеренно не добавлены: их создание входит в задание. После отправки только стартового проекта запусков во вкладке Actions ещё не будет. Они появятся после добавления workflow.

Тест проверяет `Calculator.Add`, но не HTTP-маршрут и не конфигурацию. Поэтому включение имитации сбоя не ломает модульный тест; неисправность обнаруживает smoke-test. Это предусмотренный сценарий лабораторной.
